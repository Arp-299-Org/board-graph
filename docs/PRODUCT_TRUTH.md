# Product truth

What the product is for and what it must do. Every card reads this first. When
another doc disagrees with this one, start here and check against the design.
The owner writes it, or adopts each line before it goes in.

## Mission

One paragraph: who uses the product and what it changes for them.

## What it is

What the board does, in plain words. Name each subsystem by what it is (the
power input, the display, the audio output), since the Subsystems card tests
each one alone and all at once.

## What must be measured

Each property that no one's feel can judge (a noise floor, a latency, a
current, a timing error): what is measured, the baseline it is measured
against, the equipment and the conditions. The Subsystems card measures these.
A property listed here is never judged by feel.

## What must not change

Behavior the product already has that a board change must keep. A change that
would break one of these goes to the owner first.

## Current state

What is decided, what is built, what is planned. Say which each line is.
